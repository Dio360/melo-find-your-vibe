## 1. The PWA (done)

MELO is installable as a Progressive Web App on Android, iOS, and desktop:

| Piece | Where | What it does |
|---|---|---|
| Web manifest | `src/app/manifest.ts` | Name, icons (192/512/maskable), `display: standalone`, theme `#121212` — served at `/manifest.webmanifest` |
| Icons | `public/icons/`, `src/app/icon.png`, `src/app/apple-icon.png` | Generated by `node scripts/generate-icons.mjs` (green geometric M on dark) |
| Service worker | `public/sw.js` | Caches hashed build assets; pages are network-first with an offline fallback; **never touches API/auth/playback traffic** |
| Offline page | `public/offline.html` | Shown when a page can't be fetched offline |
| Install chip | `src/components/PwaRegistrar.tsx` | Registers the SW (production only) and shows a dismissible "Install MELO" chip; on iOS shows the Share → Add to Home Screen hint |
| Headers | `next.config.ts` | Security headers globally; `Cache-Control: no-cache` on `sw.js` so updates reach installed clients |

### Verified

- `/manifest.webmanifest` serves correct JSON with all three icons
- `/sw.js` serves with `no-cache` + `application/javascript`
- All icons + `/offline.html` return 200; head has manifest link, theme-color, apple-touch-icon
- `next build` includes `/manifest.webmanifest`, `/icon.png`, `/apple-icon.png`

### Install paths (no APK needed)

- **Android / Chrome / Edge**: the install chip appears in the bottom-right once
  the browser deems the app installable (needs HTTPS in production — localhost
  also qualifies for testing). Or browser menu → *Install app*.
- **iOS Safari**: Share → *Add to Home Screen*. The manifest + apple-icon give
  it the name and icon.
- **Desktop Chrome/Edge**: install icon in the address bar.

### Updating the service worker

`public/sw.js` has a `VERSION` constant. Bump it whenever cached behavior
changes; old caches are cleaned up on activate. `updateViaCache: 'none'` plus
the no-cache header means clients pick up new SWs on the next navigation.

## 2. The APK (Trusted Web Activity)

An Android APK that wraps the deployed web app: native icon on the home
screen, standalone display, no browser chrome (once Digital Asset Links
verify). Config lives in `android/` — see `android/README.md` for the full
runbook.

```powershell
cd android
bubblewrap update   # generates the Android project from the live manifest
bubblewrap build    # → app-release-signed.apk (+ .aab for Play Store)
```

Digital Asset Links are already wired:
`https://melo-web-dbze.onrender.com/.well-known/assetlinks.json` (from
`public/.well-known/assetlinks.json`, fingerprint of `android/melo-twa.keystore`).

### Build log

The TWA host was flipped from localhost to production
(`melo-web-dbze.onrender.com` — Render appends a random suffix to new
service names; the bare name is not available). Then:

1. `bubblewrap update` — fetched the live `manifest.webmanifest` and
   generated the Android project **in place** in `android/` (Gradle files,
   `app/`, `gradle/` — all gitignored, regenerable). Bumped versionCode to 2.
2. `bubblewrap build` with `BUBBLEWRAP_KEYSTORE_PASSWORD`/`BUBBLEWRAP_KEY_PASSWORD`
   set (skips the interactive password prompt) →
   `android/app-release-signed.apk` (0.92 MB) + `app-release-bundle.aab`.

Build-machine quirks worth remembering (all solved, see `android/README.md`):
bubblewrap's SDK validator wants `<sdk>/bin` or `<sdk>/tools` at the SDK root
(modern SDKs don't have either — an empty `<sdk>/bin` plus a forwarding
`sdkmanager.bat` shim satisfies it), it pins build-tools `36.1.0`
(pre-installed via `sdkmanager` to avoid its interactive installer), it
invokes `java.exe` unquoted (so `jdkPath` must be space-free — a junction
`C:\jdk-17` points at the real JDK), and the generated project needed
`minSdkVersion` 24 (androidbrowserhelper 2.7.4) plus an explicit
`splashScreenFadeOutDuration` in `twa-manifest.json`.

> ⚠️ **`startUrl` in `twa-manifest.json` must be `"/"` (relative).** The
> generated `app/build.gradle` computes the launch URL as
> `"https://" + hostName + startUrl`; an absolute `startUrl` yields
> `https://melo-web-dbze.onrender.comhttps://melo-web-dbze.onrender.com/`,
> which the phone renders as `ERR_NAME_NOT_RESOLVED` against the bogus host
> `melo-web-dbze.onrender.comhttps`. Found via a bug report from the first
> installed build (versionCode 4); fixed in versionCode 5.

### Alternative without any local toolchain

[PWABuilder](https://www.pwabuilder.com) — paste `https://melo-web-dbze.onrender.com`,
download the Android package. Useful on a machine without the JDK/SDK; it
produces the same kind of TWA (with its own signing key, so its own
assetlinks fingerprint).

## 3. Play Store notes (later decision)

- Play Store requires an **AAB** + Play Console account ($25 one-time) +
  passing Digital Asset Links verification.
- Sideloading the APK needs none of that — distribute the file directly.
- Before Play: replace the demo signing key (password currently in
  `android/twa-manifest.json` — Bubblewrap convention, fine for demo, not for
  store distribution).
